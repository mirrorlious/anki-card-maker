# Anki 批量制卡引擎

在浏览器中把 PDF、Word、文本与结构化资料转换为可编辑的 Anki 卡片。所有正文解析、预览和导出都在本机完成。

## 核心能力

- **教材制卡**：从章节正文中生成名词解释、简答和填空卡。
- **题库制卡**：稳健识别题号、选项、答案、考点与解析，支持自定义模板。
- **PDF + OCR**：优先读取 PDF 文本层，仅在扫描页或强制模式下调用 Tesseract OCR。
- **多格式拖拽**：可一次拖入最多 20 个 PDF、DOCX、TXT、Markdown、CSV、TSV、JSON 或 HTML 文件，并合并为本次制卡资料。
- **完整编辑**：修改全部卡片字段，支持全选、批量标签、批量分类、删除与撤销。
- **PDF 对照校订**：卡片可跳回来源页并高亮原文，支持聚焦遮罩、缩放翻页、边读边改和手工重新框选依据。
- **草稿恢复**：卡片、原文和设置自动保存在浏览器 IndexedDB 中。
- **安全导出**：原文 HTML 会被转义，可导出 Anki TXT、JSON 和现代 `.apkg` 牌组。
- **本地依赖**：PDF.js、OCR worker、SQLite WASM，以及 PDF.js 所需的 JBIG2/OpenJPEG、CMap 和字体资源均随应用构建，不再动态加载第三方脚本。
- **可选 AI 辅助**：支持 DeepSeek、本地 Ollama 与自定义 OpenAI-compatible API，生成结果必须审核后才能导出。
- **四步工作流**：导入资料、生成卡片、审核校对、导出牌组各自成页，顶部步骤条与底部任务状态会持续提示下一步。
- **统一模型中心**：API 地址、模型、密钥、连通性测试与生成参数集中配置，不再散落在制卡页面。
- **导出前质检**：统一识别空字段、无效选择题、重复卡、来源未核验和过长内容，阻塞问题修正前不会进入牌组。
- **工作区可移植**：一键备份和恢复原文、卡片、设置及 PDF 提取页；备份不包含 API Key、PDF 原文件或 AI 缓存。
- **批量审核**：跨问题、答案、标签、章节和原文搜索，支持来源、质量、类型排序以及只选择当前结果。
- **稳定性兜底**：应用异常时显示安全恢复页，保留浏览器草稿，并支持键盘跳转与减少动态效果偏好。

> OCR 首次使用仍需下载所选语言模型，浏览器随后会缓存模型。纯文本 PDF 和题库粘贴不需要 OCR。

## 快速开始

```bash
npm install
npm run dev
```

打开 `http://127.0.0.1:5173/`。

## 使用方式

1. 在“导入资料”中选择“教材背诵卡”或“题库解析卡”，然后拖入一个或多个支持的文件，也可以直接粘贴文本。
2. 进入“生成卡片”，使用本地规则、AI 候选或手工添加卡片。
3. 在“审核校对”中按全部、待审核、已批准和来源待核筛选，可编辑、批量处理并对照 PDF。
4. 在“导出牌组”中确认统计与牌组名；推荐导出 `.apkg`，也可导出 Tab 分隔 TXT 或 JSON 备份。

审核页会实时显示阻塞问题和建议复核项。无阻塞问题且来源已核验的 AI 候选可安全批量批准；批准状态不再自动代表可以导出，空问题、空答案、重复卡、选项不足或来源待核仍会被排除。

页面顶部的“备份”会下载工作区 JSON，“恢复”会先验证文件格式，再经确认替换当前工作区。恢复后原文、卡片、设置和 PDF 提取结果可以继续使用；由于浏览器不会把 PDF 二进制写入备份，如需继续可视化对照，应重新选择原 PDF。

扫描版教材建议按章处理。自动模式会检查每页文本量，只对疑似扫描页执行 OCR；处理中可随时取消，既有卡片不会被覆盖。

教材本地提取采用“知识内容优先”的严格模式：只有正文中出现明确的定义、分类、组成、包含、特征或关系表达时才生成卡片，并保留原文依据；前言、目录、版本说明、教材分章，以及主体不明的篇章连接句会直接跳过。OCR 常见的中文字间空格会在制卡前自动归并。即使本地规则没有生成卡片，已提取原文仍会保留，可继续检查文本、手工制卡或使用 AI 辅助生成候选卡。

上传 PDF 后，可点击卡片上的“PDF 第 N 页 · 定位”进入对照阅读器。自动定位成功时，原文会高亮显示；“聚焦原文”会压暗页面其他区域。若 OCR 版式复杂导致坐标不准，可翻到正确页面后点击“重新框选”，拖出新的来源区域。PDF 文件只保留在当前页面会话中，不写入草稿或上传服务器；刷新页面后如需继续对照，请重新选择原文件。

阅读器已内置 JBIG2 等扫描页解码资源。若某页仍被渲染为空白，界面会显示提示并提供“重试”，而不会静默展示白页。

## 题库模板

内置“刑法母子题”和“通用选择题”预设。高级设置中可修改：

- 题号正则；
- 选项字母范围；
- 答案、考点、解析与截断标签。

无效正则会在界面直接提示，不会启动解析。

## AI 辅助制卡

AI 位于“PDF/OCR 已完成文本提取”与“人工审核”之间，适合：

- 将长段落拆成原子知识点；
- 生成名词解释、简答、填空、辨析和案例候选卡；
- 补充章节、标签与逐字原文依据；
- 对同一段内容生成多个不同角度的问题。

DeepSeek 预设使用其 OpenAI-compatible Chat Completions 接口；也可填写任意兼容接口的 Base URL 和模型。API Key 只保存在当前页面内存中，不写入 IndexedDB 草稿、导出文件或日志。AI 卡片统一标记为“待审核”，批准前不会进入 TXT、JSON 或 `.apkg`。

为控制费用，用户可设置每个文本块的字符数、最多处理块数和每块最多卡片数。相同原文、模型、接口、提示词与生成参数会优先复用 IndexedDB 中的本地结果；缓存键不包含 API Key，也可在模型中心清空或主动忽略缓存重新请求。

所有模型请求统一经过同一调用层：支持 5–120 秒超时、0–4 次自动重试，并只重试网络、限流和服务端临时故障；密钥错误、模型不存在和请求参数错误会立即停止。连接测试会显示响应模型和耗时，生成过程会展示当前文本块、请求阶段和重试次数。接口返回内容还会经过本地 JSON 校验、去重与原文引用核验。

[DeepSeek API 文档](https://api-docs.deepseek.com/zh-cn/) · [DeepSeek JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode)
